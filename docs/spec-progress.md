# dinii 互換ダッシュボード 実装状況

いただいた開発指示書（`dinii-spec.zip` 同梱の SPEC.md / 60 枚のスクリーンショット）に対する
実装の進み具合を記録する。指示書そのものはリポジトリには含めていない（実データのスクリーン
ショットを含むため）。手元の `SPEC.md` を正として参照すること。

## 最初に整理したこと

指示書 §1.1 に、**ダッシュボードと店舗端末は別プロダクト**と明記されている。

> 店舗側の端末（レジ・ハンディ・キッチンプリンター・キオスク）と顧客向けモバイルオーダー
> （LINE ミニアプリ想定）は別プロダクトだが、本ダッシュボードがそれらの
> マスター設定・集計・分析・CRM 配信 を一手に担う。

これまで作ってきた POS レジ・KDS・モバイルオーダーは**端末側**にあたる。
指示書が対象にしているのは**管理ダッシュボード**で、両者は置き換え関係にない。
そこでリポジトリをモノレポに分けた（§14 の `apps/dashboard/` に倣う）。

```
apps/
  dashboard/   この指示書が対象とする管理ダッシュボード（:3000）
  terminal/    POSレジ / KDS / モバイルオーダー（:3001）
supabase/      両者が共有するスキーマ
```

## 指示書との差異（意図的なもの）

1. **認証が Supabase Auth ではない。**
   §10.1 は Supabase Auth（招待メール）を前提にしているが、招待メールの導線が未整備のため、
   暫定として `accounts.password_hash`（bcrypt）と HMAC 署名 Cookie で実装した。
   `auth.users` へ移す際は `src/lib/auth.ts` と `verify_account_password` を差し替える。

2. **開店・閉店時刻を `time` ではなく「0:00 からの分」で持つ。**
   §5.12 は閉店 24:00〜 を許容し 31:00（＝翌 7:00）の形で表示するが、
   Postgres の `time` は 24:00:00 までしか持てない。そのため
   `shops.open_time_min` / `close_time_min` と `business_hours` を分単位の整数
   （0〜1860）にし、画面では `HH:MM` の文字列で出し入れする。
   antd の TimePicker も 24 時超を扱えないので、専用の `TimeMinInput` を用意した。

3. **メニューの税率が指示書と二本立てになっている。**
   §5.3 / §8.2 では税率は商品ごとの固定値（10% / 8%）だが、
   これまでに実装した「持ち帰りなら飲食料品だけ 8%」の動的判定も残している
   （`menus.reduced_rate_eligible`）。持ち帰りのある業態では動的判定の方が
   正しいため、`place_order` は
   「持ち帰り かつ reduced_rate_eligible なら店舗の軽減税率、それ以外は `menus.tax_rate`」
   の順で決める。

4. **注文明細の選択肢を jsonb で持っている。**
   §8.5 には `order_item_choices` テーブルがあるが、現状は
   `order_items.options_snapshot`（jsonb）にスナップショットしている。
   伝票・レシート・KDS が動いているため、移行は必要になった時点で行う。

5. **ダッシュボード本体（§5.1）は器のみ。**
   KPI カード 11 種・推移チャート・ランキングは日次集計テーブルが前提のため P3。

6. **レジ操作用パスワードはハッシュだけを保存する。**
   §5.12 の「ドロワーオープン / VOID / テーブルクリア」は `set_shop_password()`
   経由で bcrypt ハッシュのみを書き込み、画面へは「設定済みかどうか」しか返さない。

7. **支払方法等設定を 4 つの URL ではなく 1 画面のタブにした。**
   §5.10 は `/onSitePaymentDetailType` など 4 つの URL に分かれているが、
   ナビゲーション上は「支払方法等設定」の 1 項目なので、`/paymentTypes` の
   タブにまとめた。中身と並びは指示書どおり。

8. **ロゴ・ブランド名・画像素材は流用していない**（指示書冒頭の注意書きに従う）。

## 動かし方

```bash
npm install
npm run dev            # ダッシュボード http://localhost:3000
npm run dev:terminal   # 店舗端末     http://localhost:3001
```

Supabase が未設定ならどちらもデモモードで動く。
ダッシュボードのデモログインは `owner@example.com` / `demo1234`。
