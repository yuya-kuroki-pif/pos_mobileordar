# 0001. 税計算と営業日を追補に合わせる

- 日付: 2026-09-24
- 状態: 採用

## 背景

追補（SPEC_ADDENDUM）§0.2 に「本書が本編と矛盾する場合は本書を優先」とある。
すでに作ってあった以下が追補と食い違っていた。

- 営業日変更時刻が 05:00（追補は 07:00）
- 税区分が内税/外税の 2 値（追補は 4 値。非課税・不課税を含む）
- 税を会計単位でまとめて計算（追補は明細単位で切捨て）

## 決めたこと

1. **営業日変更時刻は 07:00**。`shops.business_day_start_time time` で店舗ごとに持つ。
   時（integer）ではなく time にしたのは、24 時間営業店の個別調整に対応するため。
2. **税区分は 4 値**。不課税はメニューに設定できないよう check 制約で禁止した
   （推しエール・チップ専用のため）。
3. **税は明細単位で切捨て、選択肢は本体と別計算**。
4. **計算は整数だけで行う**。`748 * 0.1 / 1.1` は浮動小数点で 67.999… になり、
   切り捨てると 67 円と出て仕様の 68 円に合わなかった。
   税率を % の整数に直して `floor(価格 * pct / (100 + pct))` で計算する。
5. 会計まわりの計算は `packages/pos-core` に置き、ダッシュボードと店舗端末の両方から呼ぶ。
   追補 §A.6.3 が「フロント PWA とサーバー RPC で同一実装」を求めているため。
6. 全取引テーブルに `calc_version` を持たせた。式を変えても過去の伝票を再現できるようにする。

## 確かめ方

`packages/pos-core/test/tax.test.ts` に、追補に載っている計算例をそのまま入れてある。

```bash
npx tsx packages/pos-core/test/tax.test.ts
```

## まだやっていないこと

- SQL 側の `calc_session_total` は税率ごとに合算する旧方式のまま。
  レジの会計処理を追補に合わせるときに、この計算も pos-core と同じ式へ差し替える。
- 集計基準の二重化（営業日基準 / レジ精算単位）は列を足しただけで、
  画面ごとの使い分けはこれから。
